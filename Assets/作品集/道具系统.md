# 道具系统 — 作品集视频台词

> 模块：道具系统（Item System）
> 技术栈：Unity / C# / ScriptableObject / 策略模式 / 观察者模式 / MVC分层
> 预计时长：4-5分钟

---

## 一、开场总览

`【画面：游戏实机录制 — 玩家在场景中行走，路遇道具，走近后弹出操作提示，按F拾取、按E直接使用；切到背包面板，展示道具按等级分行排列，鼠标悬停查看详情，点击使用后角色面板出现Buff图标并倒计时】`

本项目的道具系统实现了从数据定义、效果执行、拾取交互、背包管理，到UI展示与存档持久化的完整功能闭环。系统设计遵循三个核心原则：高度可扩展、策划零代码配置、模块间完全解耦。

---

## 二、数据驱动设计 — ScriptableObject

`【画面：切到Unity编辑器 — Project窗口中展示ItemData的.asset文件列表（润心草、生命药剂、吸血鬼之牙、疾步之靴）；选中"吸血鬼之牙"在Inspector中展示字段配置】`

`【画面：展示ItemData.cs源码，高亮 [CreateAssetMenu] 特性与字段定义】`

道具的数据层基于 ScriptableObject 实现。每个道具对应一个独立的 .asset 资产文件，通过 `[CreateAssetMenu]` 特性注册到编辑器右键菜单，策划无需编写任何代码即可创建新道具。

ItemData 定义了道具的全部配置字段：

- **ItemName / ItemIcon / ItemDescription** — 名称、图标、描述，用于UI展示
- **ItemLevel（1~3）** — 道具等级，背包UI按等级分三行展示
- **BagLimit** — 持有上限，每种道具独立配置堆叠上限，防止刷道具
- **Effects 数组** — 效果列表，一个道具可组合挂载多种效果

`【画面：Inspector中展开"吸血鬼之牙"的Effects数组，展示其中拖入的LifestealBuffEffect资产引用】`

该设计的核心优势在于数据与逻辑的彻底分离。以项目现有道具为例："润心草"配置了恢复10点生命值的效果，"生命药剂"配置了恢复20点生命值的效果，"吸血鬼之牙"配置了攻击回5%最大生命值持续10秒的效果，"疾步之靴"配置了2倍移速持续10秒的效果——全部为纯数据配置，零代码。

## 三、策略模式 — 效果系统

`【画面：切到代码编辑器 — 展示ItemEffect.cs，高亮 abstract class ItemEffect 与 Apply/Remove 抽象方法签名】`

`【画面：依次展示三个子类文件 — HealEffect.cs、TimedBoostEffect.cs、LifestealBuffEffect.cs 的类定义与关键逻辑】`

效果系统是道具系统的核心，采用策略模式实现。

抽象基类 `ItemEffect` 继承自 ScriptableObject，定义了两个抽象方法：`Apply(GameObject target)` 用于施加效果，`Remove(GameObject target)` 用于移除效果。每种效果类型是一个独立的子类：

- **HealEffect** — 即时治疗效果。Apply 中直接修改 PlayerStat 的 HP，RegisterBuff 以即时模式注册到 BuffTracker（UI显示"已使用"而非读秒）；Remove 为空操作。
- **TimedBoostEffect** — 定时增益效果。Apply 中按倍率修改对应属性（移速/伤害），挂载内部协程载体组件 `TimedBoostRunner` 驱动倒计时，到期后调用 Remove 恢复原始属性值。
- **LifestealBuffEffect** — 攻击回血效果。Apply 中挂载 `LifestealBuffRunner` 组件，该组件在 OnEnable 时监听 `EnemyHurt` 事件，持续期间每次攻击命中触发按最大生命值比例回血；重复触发时刷新持续时间而非叠加。

`【画面：回到Unity编辑器 — 演示新建一个ItemEffect子类资产的过程（右键 → Create → Item → 选择效果类型 → 在Inspector中配置参数）】`

该设计遵循开闭原则：新增效果类型时只需继承 ItemEffect 编写子类，无需修改任何现有代码。随后策划在 ItemData 的 Effects 数组中拖入新效果资产即可完成配置。

此外，Effects 数组支持组合挂载。策划可为一个道具配置多种效果，例如同时挂载增伤与吸血，实现复合型道具——效果之间互不干扰，各自独立执行。

每个效果还配置了 `EffectCategory`（None/Buff/Debuff）与 `BriefDescription`，决定了其在角色面板上的显示位置与描述文本。

## 四、事件驱动架构 — EventCenter

`【画面：展示EventCenter.cs源码 — 高亮 Dictionary<EventName, Delegate> 事件表、AddListener/RemoveListener/Invoke 泛型方法】`

`【画面：展示EventName枚举中与道具相关的事件项 — ItemPickUp、ItemUse、BagChanged、ShowTips、HideTips】`

道具系统中所有模块间的通信通过全局事件中心 EventCenter 完成，基于观察者模式实现。

EventCenter 内部维护 `Dictionary<EventName, Delegate>` 事件表，通过 `Delegate.Combine` / `Delegate.Remove` 管理多播委托，支持泛型参数 `Action<T>` 与无参 `Action` 两种回调形式。所有事件名通过 EventName 枚举统一管理，避免字符串硬编码带来的维护风险。

`【画面：游戏实机录制 — 玩家走近道具，画面右侧弹出提示面板；按F拾取后背包UI刷新；逐步标注事件触发链路】`

以拾取流程为例，完整的事件链路如下：

1. 玩家进入 Trigger 范围 → ItemPickup 调用 `Invoke(EventName.ShowTips, ItemData)` → TipsUI 监听到事件，显示道具名称、描述与操作指引
2. 玩家按 F 键 → BagSystem.AddItem 执行数据层添加 → 成功后依次 `Invoke(EventName.ItemPickUp)` 与 `Invoke(EventName.BagChanged)` → BagUI 监听到 BagChanged 自动刷新背包格子
3. 玩家离开范围 → `Invoke(EventName.HideTips)` → TipsUI 隐藏提示面板

整个链路中，道具实体不直接引用背包UI，背包UI也不直接引用道具实体，各方仅通过事件解耦通信。新增功能时只需监听对应事件，无需修改既有模块。

## 五、背包系统 — MVC分层架构

`【画面：依次展示三个文件的类定义 — BagData.cs（Model层）、BagSystem.cs（Controller层）、BagUI.cs（View层），标注分层关系】`

背包系统采用 MVC 分层架构：

`【画面：展示BagData.cs — 高亮 Dictionary<ItemData, int>、AddItem/RemoveItem/GetCount/GetItemsByLevel 方法】`

**Model 层 — BagData**：纯数据逻辑类，内部以 `Dictionary<ItemData, int>` 存储道具与数量。提供增删查接口，AddItem 中校验 BagLimit 堆叠上限，RemoveItem 归零时自动清除字典条目避免残留。GetItemsByLevel 按等级筛选，供UI分层展示使用。不依赖任何 Unity 生命周期，可独立单元测试。

`【画面：展示BagSystem.cs — 高亮单例初始化、AddItem/UseItem/ApplyEffects/Save/Load 方法】`

**Controller 层 — BagSystem**：单例 MonoBehaviour，是背包系统的对外入口。将数据操作委托给 BagData，在操作完成后广播对应事件通知UI刷新。UseItem 方法中先校验数量、再扣减、再依次遍历 Effects 数组调用 Apply、最后广播事件——保证状态一致性。同时负责存档读写，监听 SaveGame / LoadGame 事件。

`【画面：展示BagUI.cs — 高亮 EventCenter.AddListener(EventName.BagChanged, Refresh)、CreateSlotsForLevel、ClearSlots 逻辑】`

**View 层 — BagUI / BagSlot / TipsUI**：纯表现层。BagUI 监听 BagChanged 事件自动刷新——刷新时先 ClearSlots 销毁全部格子实例，再按三个等级分别从 BagData 取数据创建 BagSlot。BagSlot 处理左键点击使用与鼠标悬停提示，通过回调委托给 BagUI 而非直接操作 BagSystem。TipsUI 管理场景内道具提示与通关提示。

`【画面：游戏实机录制 — 打开背包面板，展示三个等级区域的道具格子，悬停显示Tooltip，点击使用后格子消失或数量减少】`

分层架构的优势在于职责隔离：若需将UI从列表视图改为网格视图，仅需修改 View 层，Model 与 Controller 完全不受影响。

## 六、存档系统 — JSON序列化

`【画面：展示BagSystem.cs中Save/Load方法 — 高亮 BagSaveData 结构、JsonUtility.ToJson/FromJson、FindItemByName 逻辑】`

`【画面：打开文件资源管理器，展示 persistentDataPath 下的 bag_save.json 文件内容】`

背包存档采用 JSON 序列化方案。存档结构 `BagSaveData` 仅包含 `BagEntry[]` 数组，每条记录道具名称与数量。

ScriptableObject 作为引擎资源无法直接 JSON 序列化，因此存档时仅写入道具名称字符串，读档时通过 `FindItemByName` 在预配置的 AllItemData 数组中遍历查找，还原为 ScriptableObject 引用。这一设计在保证存档文件轻量的同时，确保了反序列化时引用的正确恢复。

系统在 `OnApplicationQuit` 时自动保存，同时支持通过 SaveGame / LoadGame 事件手动触发存读档。

## 七、Buff追踪系统 — BuffTracker

`【画面：展示BuffTracker.cs源码 — 高亮 BuffEntry 结构体、Register/Unregister 方法、Update中的倒计时逻辑】`

`【画面：游戏实机录制 — 使用"疾步之靴"后角色面板出现移速增益Buff图标并倒计时；使用"润心草"后出现"已使用"标记闪现2秒后消失】`

道具效果生效后，BuffTracker 负责在角色面板上追踪并展示当前活跃的 Buff/Debuff。

BuffTracker 挂载在玩家 GameObject 上，内部维护 `List<BuffEntry>` 列表。每条 BuffEntry 为 struct，记录来源效果引用、描述文本、分类、剩余时间、总时间、是否为即时效果。

效果子类在 Apply 中调用 `RegisterBuff` 注册，在 Remove 中调用 `UnregisterBuff` 注销。同一效果重复触发时刷新持续时间，而非新增条目。Update 中每帧递减剩余时间，归零后自动移除条目。UI 层每帧从 `GetActiveBuffs` 只读列表读取数据渲染。

即时效果（如回血）标记 `IsInstant = true`，UI 显示"已使用"标记而非读秒倒计时。持续效果则显示剩余时间进度条。

BuffEntry 使用 struct 而非 class，避免了每帧更新的 GC 开销。

## 八、拾取交互 — ItemPickup

`【画面：展示ItemPickup.cs源码 — 高亮 OnTriggerEnter2D/OnTriggerExit2D、Update中的浮动动画与F/E键交互逻辑】`

`【画面：游戏实机录制 — 道具在场景中上下浮动；玩家走近弹出提示；分别演示F键拾取（道具消失，背包中出现）与E键直接使用（道具消失，角色面板出现Buff）】`

场景中的道具实体挂载 ItemPickup 组件，职责包括：

- **浮动动画** — Start 时记录初始位置，Update 中以正弦函数驱动 Y 轴偏移，实现道具上下浮动效果
- **Trigger 检测** — OnTriggerEnter2D 检测玩家进入范围，通过事件通知UI显示提示；OnTriggerExit2D 通知隐藏
- **双键交互** — F 键拾取存入背包（BagSystem.AddItem 成功后销毁道具实体）；E 键直接使用不占背包格子（ApplyEffects 后销毁）
- **自动图标配置** — Start 时根据 ItemData.ItemIcon 自动设置 SpriteRenderer

双键交互设计赋予玩家选择权：稀有道具可存入背包留到关键时刻使用，普通回复道具可就近直接使用。

## 九、技术亮点总结

`【画面：依次弹出以下要点文字，配合对应代码片段或实机画面的快速回切】`

1. **ScriptableObject 数据驱动** — 策划零代码配置道具，数据与逻辑彻底分离，支持运行时热引用
2. **策略模式效果系统** — 遵循开闭原则，新增效果类型不改旧代码；Effects 数组支持效果组合，实现复合型道具
3. **观察者模式事件中心** — 全局事件总线，模块间零耦合；EventName 枚举统一管理，避免硬编码
4. **MVC 分层架构** — Model（BagData）/ Controller（BagSystem）/ View（BagUI）各司其职，便于维护与扩展
5. **JSON 存档系统** — 名称序列化 + FindItemByName 引用还原，存档轻量且反序列化准确
6. **BuffTracker 追踪系统** — struct 存储无 GC 压力，支持即时/持续双模式，自动倒计时与过期清理
7. **双键交互设计** — 拾取与直接使用分离，提升玩家决策体验

`【画面：回到游戏实机全景 — 玩家使用多个道具，背包管理、Buff栏实时更新、效果生效的完整流程演示】`

整个道具系统从数据配置到运行时逻辑到UI表现，形成完整闭环，各环节保持高度可扩展性与可维护性。
