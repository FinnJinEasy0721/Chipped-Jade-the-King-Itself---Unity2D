# 祝福系统文档

> 本文档面向策划与程序，说明祝福系统的架构设计、每个脚本的职责，以及策划如何在 Unity Inspector 中配置祝福数据。

---

## 一、系统总览

祝福系统是一个**数据驱动 + 策略模式**的全局 Buff 框架。玩家同时只能拥有 **1 个祝福**，在过渡关卡的美琴（天使）处用金币购买新祝福后替换旧的。每个祝福可同时包含**多个被动效果**和**一个主动技能**。

### 设计模式

| 模式 | 用途 |
|---|---|
| 数据驱动 | `BlessingDatabase` SO 集中管理所有祝福配置，策划在 Inspector 填参数即可 |
| 策略模式 | `EffectHandlerBase` / `SkillHandlerBase` 抽象基类 + 具体子类，新增效果/技能不改动核心 |
| 工厂模式 | `EffectHandlerFactory` / `SkillHandlerFactory` 注册枚举→处理器映射 |
| 观察者模式 | 通过 `EventCenter` 接入战斗事件（攻击命中/受击/击杀），效果处理器订阅事件触发 |
| 修饰器模式 | `StatModifierSystem` 管理所有属性修改器（加法/乘法/覆盖） |
| 组件模式 | `BuffContainer` 挂载到敌人上，独立管理所有 debuff |

## 二、脚本说明

### 2.1 数据层（Data/）

#### `BlessingEnums.cs` — 枚举定义

定义了祝福系统所有枚举，是整个系统的"词汇表"：

| 枚举 | 说明 | 值 |
|---|---|---|
| `EffectType` | 被动效果做什么 | StatModifier / Lifesteal / DotOnHit / AuraDamage / ReflectDamage |
| `EffectTriggerType` | 被动效果何时触发 | Permanent / OnAttackHit / OnPlayerHurt / OnEnemyKill / Tick |
| `SkillType` | 主动技能类型 | None / DamageArea / Invincibility / StatBoost / EnemyDebuff / Knockback |
| `SkillDurationType` | 技能持续方式 | Timed（定时）/ OneShot（一次）/ Toggle（再按取消）/ ManualClose（手动关闭） |
| `HealthCostType` | 血量消耗方式 | None / CurrentHPPct / MaxHPPct / Flat |
| `DamageScaleType` | 伤害缩放依据 | Flat / PlayerAttack1~3Pct / PlayerHeavyPct / EnemyMaxHPPct / EnemyCurHPPct |
| `StatType` | 可修改的属性 | MaxHP / MoveSpeed / JumpForce / CritRate / CritMultiplier / AttackPower / HeavyAttackCD |
| `ModifierOp` | 属性修改操作 | AddFlat / AddPercentage / Multiply / Override |
| `AreaShape` | 范围形状 | Circle / Rectangle |

#### `BlessingConfigs.cs` — 效果与技能配置结构

两个 `[Serializable]` 类，定义了策划在 Inspector 中看到的参数字段：

- **`BlessingEffectConfig`**：被动效果配置。包含效果类型、触发时机、属性修改参数、伤害参数、范围参数、回血参数。不同效果类型使用不同的参数区域。
- **`BlessingSkillConfig`**：主动技能配置。包含技能类型、持续方式、CD、血量消耗、技能伤害、范围、附带效果（眩晕/击退）、属性增强参数。

#### `BlessingData.cs` — 祝福数据结构

单个祝福的完整定义：
- 基础信息：`blessingID`（唯一标识，用于存档）、`blessingName`、`description`、`icon`、`cost`（购买价格）
- 被动效果列表：`List<BlessingEffectConfig> passiveEffects`（可包含多个）
- 主动技能：`BlessingSkillConfig skillConfig`（一个）

#### `BlessingDatabase.cs` — 集中数据库 SO

**策划的主入口**。`[CreateAssetMenu]` SO，创建方式：Project 窗口右键 → `Create > Blessing > BlessingDatabase`。

内部是一个 `List<BlessingData> blessings`，策划在此列表中添加所有祝福条目。提供 `FindByID(string id)` 方法供运行时查找。

---

### 2.2 运行时核心（Runtime/）

#### `BlessingRuntimeContext.cs` — 运行时上下文

一个普通 C# 类，缓存玩家相关引用（GameObject、PlayerStat、StatModifierSystem、BlessingDatabase、Transform），传递给所有 Handler，避免每个 Handler 自己查找组件。

#### `StatModifierSystem.cs` — 属性修改器系统

管理所有属性修饰器，计算最终属性值。核心方法 `GetFinalValue(StatType, baseValue)`，计算顺序：

```
基础值 → AddFlat(累加) → AddPercentage(基于基础值的百分比) → Multiply(叠乘) → Override(覆盖)
```

支持按来源（`object Source`）批量移除修改器，卸下祝福时一键清除该祝福的所有属性加成。

#### `SkillController.cs` — 主动技能控制器

管理技能的 CD、血量消耗、持续生命周期。关键方法：
- `TryActivate()`：检查 CD + 血量消耗，返回是否可释放（Toggle 型已激活时再按则关闭）
- `OnSkillAnimationComplete()`：动画播完后实际激活效果
- `CustomUpdate()`：每帧驱动 CD 倒计时和 Timed 型持续时间

#### `BlessingManager.cs` — 核心管理器

**挂载于 Player**（`[RequireComponent(typeof(PlayerStat))]`）。职责：
- 装备/卸下祝福（`EquipBlessing` / `UnequipCurrent`）
- 为每个被动效果创建对应的 Handler 实例
- 注册/反注册战斗事件监听
- 驱动 Tick 型效果（光环等）
- 存档/读档（祝福 ID 写入 `player.json`）
- Debug 范围可视化（Inspector 开关 `_showDebugGizmos`）

---

### 2.3 被动效果处理器（Effects/）

#### `EffectHandlerBase.cs` — 抽象基类 + 工厂

定义三个生命周期方法：`OnEquip`（装备时）、`OnUnequip`（卸下时）、`OnTrigger`（事件触发时）。

内置 `EffectHandlerFactory`，通过 `EffectType` 枚举创建对应处理器实例。新增效果类型只需：①加枚举值 → ②继承基类 → ③工厂注册一行。

#### 具体处理器

| 文件 | 类名 | 效果说明 | 触发时机 |
|---|---|---|---|
| `StatModifierHandler.cs` | `StatModifierHandler` | 修改属性（+伤害/+暴击率/+生命上限/+移速等） | Permanent（装备即生效） |
| `LifestealHandler.cs` | `LifestealHandler` | 攻击命中时按伤害比例/最大血量比例回血 | OnAttackHit |
| `DotOnHitHandler.cs` | `DotOnHitHandler` | 攻击命中时给敌人施加持续伤害 Buff | OnAttackHit |
| `AuraDamageHandler.cs` | `AuraDamageHandler` | 在玩家周围创建持续伤害区域，每 Tick 造成伤害 | Tick |
| `ReflectDamageHandler.cs` | `ReflectDamageHandler` | 受击时对攻击者造成伤害 | OnPlayerHurt |

---

### 2.4 主动技能处理器（Skills/）

#### `SkillHandlerBase.cs` — 抽象基类 + 工厂

定义 `Activate`（激活）、`Deactivate`（停用）、`Tick`（每帧持续效果）三个方法。内置 `SkillHandlerFactory`。

#### `SkillHandlers.cs` — 5 种具体技能

| 类名 | 技能类型 | 说明 |
|---|---|---|
| `DamageAreaSkillHandler` | DamageArea | 对范围内敌人造成伤害，可附带眩晕/击退，持续型每 Tick 重复 |
| `InvincibilitySkillHandler` | Invincibility | 激活后玩家无敌，停用后恢复 |
| `StatBoostSkillHandler` | StatBoost | 激活时添加属性修改器（如暴击率+50%），停用时移除 |
| `EnemyDebuffSkillHandler` | EnemyDebuff | 对范围内敌人施加减益 Buff（减攻击力等） |
| `KnockbackSkillHandler` | Knockback | 对范围内敌人施加击退力 + 眩晕 |

---

### 2.5 敌人 Buff 系统（Enemy/）

#### `BuffContainer.cs` — 敌人 Buff 容器

挂载于敌人（`[RequireComponent(typeof(EnemyStatBase))]`），由 `EnemyStatBase.Awake` 自动添加。管理所有持续效果：
- `BuffType`：DOT（持续伤害）/ Stun（眩晕）/ StatReduction（属性削弱）/ Slow（减速）
- `AddBuff(BuffInstance)`：添加 Buff，自动 Tick 和到期清理
- `HasBuff(BuffType)`：查询是否有指定类型 Buff（供敌人 AI 检查）

---

### 2.6 战斗事件与工具（Combat/）

#### `CombatContext.cs` — 战斗上下文结构体

作为战斗事件的参数传递，包含：Attacker（攻击者）、Target（被攻击者）、Damage（伤害值）、IsCrit（是否暴击）、ComboStage（攻击段数 0=重击 1~3=连击）。

#### `CombatEventBridge.cs` — 战斗事件桥接器

静态工具类，在战斗发生时调用对应方法触发 `EventCenter` 全局事件：
- `OnPlayerAttackHit` → 触发 `EnemyHurt` 事件
- `OnEnemyAttackHit` → 触发 `PlayerHurt` 事件
- `OnEnemyDie` → 触发 `EnemyDie` 事件
- `OnPlayerDie` → 触发 `PlayerDie` 事件

祝福系统的被动效果通过订阅这些事件来触发（如攻击回血、命中 DOT、受击反伤、击杀回血等）。

#### `DamageCalculator.cs` — 伤害计算 + 范围检测工具

两个静态工具类：
- `DamageCalculator.CalculateDamage()`：根据 `DamageScaleType` 计算伤害（固定值/各段攻击力%/敌人血量%等）
- `AreaUtility.GetTargetsInArea()`：根据形状（圆形/矩形）检测范围内敌人，支持限制最大目标数（取最近的 N 个）

## 三、策划配置指南

### 3.1 创建 BlessingDatabase 资产

1. 在 Project 窗口中右键 → `Create > Blessing > BlessingDatabase`
2. 将新创建的 SO 资产命名为 `BlessingDatabase`（或任意名称）
3. 双击打开，在 Inspector 中看到 `Blessings` 列表

### 3.2 添加祝福条目

在 `Blessings` 列表中点击 `+` 添加一个祝福条目，填写以下字段：

#### 基础信息

| 字段 | 说明 | 示例 |
|---|---|---|
| `Blessing ID` | 唯一标识符，**必须唯一**，用于存档 | `fire_blessing` |
| `Blessing Name` | 祝福名称 | `烈焰之祝福` |
| `Description` | 祝福描述（TextArea） | `攻击命中后造成持续燃烧伤害` |
| `Icon` | 祝福图标 Sprite | 拖入 Sprite |
| `Cost` | 购买价格（金币） | `500` |

#### 被动效果列表（Passive Effects）

点击 `+` 添加被动效果。每个效果需要配置：

**第一步：选择效果类型和触发时机**

| 效果类型 (Effect Type) | 建议触发时机 (Trigger Type) | 说明 |
|---|---|---|
| `StatModifier` | `Permanent` | 永久属性加成（+伤害/+暴击/+血上限等） |
| `Lifesteal` | `OnAttackHit` | 攻击命中时回血 |
| `DotOnHit` | `OnAttackHit` | 命中施加持续伤害 |
| `AuraDamage` | `Tick` | 范围光环持续伤害 |
| `ReflectDamage` | `OnPlayerHurt` | 受击时反伤 |

**第二步：根据效果类型填写参数**

###### StatModifier（属性修改）需要填写的字段：

| 字段 | 说明 | 示例值 |
|---|---|---|
| `Stat Type` | 要修改的属性 | `CritRate`（暴击率） |
| `Modifier Op` | 修改方式 | `AddFlat`（加固定值） |
| `Modifier Value` | 数值 | `0.2`（+20% 暴击率） |

`Modifier Op` 说明：
- `AddFlat`：加固定值。如 MaxHP +50、CritRate +0.2
- `AddPercentage`：加基础值的百分比。如基础暴击率 0.05，+0.2 表示 +0.05×0.2=+0.01
- `Multiply`：乘法。如移速 ×1.5
- `Override`：直接覆盖为指定值。如设暴击率 = 0（无法暴击）

###### Lifesteal（攻击回血）需要填写的字段：

| 字段 | 说明 | 示例值 |
|---|---|---|
| `Lifesteal Ratio` | 回血占伤害的比例 | `0.1`（回伤害的 10%） |
| `Lifesteal Max HP Ratio` | 回血占自身最大血量的比例 | `0.05`（回最大血量的 5%） |

两个字段可同时填写，回血量 = 伤害×Ratio + 最大血量×MaxHPRatio。

###### DotOnHit（命中施加 DOT）需要填写的字段：

| 字段 | 说明 | 示例值 |
|---|---|---|
| `Damage Scale Type` | 伤害缩放依据 | `EnemyMaxHPPct`（敌人最大血量的百分比） |
| `Damage Scale` | 缩放比例 | `0.05`（每 Tick 造成敌人最大血量 5% 的伤害） |
| `Duration` | DOT 持续时间（秒） | `3` |
| `Tick Interval` | 每 Tick 间隔（秒） | `1`（每秒掉一次血） |

`Damage Scale Type` 说明：
- `Flat`：固定数值（如每 Tick 造成 20 点伤害）
- `PlayerAttack1Pct` / `2Pct` / `3Pct`：玩家第一/二/三段攻击力的百分比
- `PlayerHeavyPct`：玩家蓄力重击攻击力的百分比
- `EnemyMaxHPPct`：敌人最大血量的百分比
- `EnemyCurHPPct`：敌人当前血量的百分比

###### AuraDamage（范围光环）需要填写的字段：

| 字段 | 说明 | 示例值 |
|---|---|---|
| `Damage Scale Type` | 伤害缩放依据 | `PlayerAttack1Pct` |
| `Damage Scale` | 缩放比例 | `0.2`（每 Tick 造成攻击力 20% 的伤害） |
| `Tick Interval` | 每 Tick 间隔（秒） | `0.5` |
| `Area Shape` | 范围形状 | `Circle` |
| `Area Radius` | 圆形半径 | `3` |
| `Area Width` / `Area Height` | 矩形宽/高（仅 Rectangle） | `3` / `2` |
| `Center On Player` | 是否以玩家为中心 | `true` |
| `Max Targets` | 最大目标数，0=无限 | `0` |

###### ReflectDamage（反伤）需要填写的字段：

| 字段 | 说明 | 示例值 |
|---|---|---|
| `Damage Scale Type` | 伤害缩放依据 | `Flat` |
| `Damage Scale` | 缩放比例/固定值 | `10`（固定反伤 10 点） |

#### 主动技能配置（Skill Config）

| 字段 | 说明 | 示例值 |
|---|---|---|
| `Skill Type` | 技能类型 | `DamageArea`（范围伤害） |
| `Duration Type` | 持续方式 | `OneShot`（瞬间生效） |
| `Duration` | 持续时间（仅 Timed 生效） | `5` |
| `Cooldown` | 冷却时间（秒） | `20` |
| `Health Cost Type` | 血量消耗方式 | `None` |
| `Health Cost Value` | 消耗数值 | `0` |
| `Damage Scale Type` | 伤害缩放依据 | `Flat` |
| `Damage Scale` | 缩放比例/固定值 | `300` |
| `Area Shape` | 范围形状 | `Circle` |
| `Area Radius` | 圆形半径 | `5` |
| `Max Targets` | 最大目标数 | `3` |
| `Stun Duration` | 眩晕时间（秒），0=不眩晕 | `3` |
| `Knockback Force` | 击退力度，0=不击退 | `0` |
| `Boost Stat` | 增强属性（仅 StatBoost） | `CritRate` |
| `Boost Op` | 增强方式 | `AddFlat` |
| `Boost Value` | 增强数值 | `0.5` |

`Skill Type` 说明：
- `None`：无主动技能（纯被动祝福）
- `DamageArea`：对范围内敌人造成伤害，可附带眩晕/击退
- `Invincibility`：自身无敌
- `StatBoost`：属性增强（如暴击率+50%持续30秒）
- `EnemyDebuff`：对敌人施加减益
- `Knockback`：击退+眩晕

`Duration Type` 说明：
- `Timed`：持续 N 秒后自动结束
- `OneShot`：瞬间生效，无持续时间
- `Toggle`：再次按 L 键切换开关
- `ManualClose`：需手动关闭（长按等条件）

`Health Cost Type` 说明：
- `None`：不消耗血量
- `CurrentHPPct`：消耗当前血量的百分比
- `MaxHPPct`：消耗最大血量的百分比
- `Flat`：消耗固定数值血量

### 3.3 配置示例

#### 示例 1：纯被动祝福 — 「攻击祝福」

```
Blessing ID: atk_blessing
Blessing Name: 攻击祝福
Cost: 300

Passive Effects:
  [0] EffectType: StatModifier
      TriggerType: Permanent
      StatType: AttackPower
      ModifierOp: AddPercentage
      ModifierValue: 0.1         ← 攻击力 +10%

Skill Config:
  SkillType: None                ← 纯被动，无主动技能
```

#### 示例 2：被动+主动 — 「碎玉焚心」

```
Blessing ID: crit_blessing
Blessing Name: 碎玉焚心
Cost: 800

Passive Effects:
  [0] EffectType: StatModifier
      TriggerType: Permanent
      StatType: AttackPower
      ModifierOp: AddPercentage
      ModifierValue: 2.0         ← 攻击力 +200%

Skill Config:
  SkillType: StatBoost
  DurationType: Timed
  Duration: 30                   ← 持续30秒
  Cooldown: 60
  HealthCostType: None
  BoostStat: CritRate
  BoostOp: AddFlat
  BoostValue: 0.5                ← 暴击率 +50%
```

#### 示例 3：DOT + 范围技能 — 「惊世先生」

```
Blessing ID: lightning_blessing
Blessing Name: 惊世先生
Cost: 1000

Passive Effects:
  [0] EffectType: StatModifier
      TriggerType: Permanent
      StatType: AttackPower
      ModifierOp: AddPercentage
      ModifierValue: 0.4         ← 攻击力 +40%

  [1] EffectType: StatModifier
      TriggerType: Permanent
      StatType: CritRate
      ModifierOp: Override
      ModifierValue: 0           ← 无法暴击

Skill Config:
  SkillType: DamageArea
  DurationType: OneShot
  Cooldown: 20
  DamageScaleType: Flat
  DamageScale: 300               ← 固定300点伤害
  AreaShape: Circle
  AreaRadius: 5
  MaxTargets: 3                  ← 最近3名敌人
  StunDuration: 3                ← 眩晕3秒
```

#### 示例 4：攻击回血 + DOT — 「生命偷取祝福」

```
Blessing ID: lifesteal_blessing
Blessing Name: 生命偷取
Cost: 600

Passive Effects:
  [0] EffectType: StatModifier
      TriggerType: Permanent
      StatType: AttackPower
      ModifierOp: AddPercentage
      ModifierValue: -0.1        ← 攻击力 -10%（代价）

  [1] EffectType: Lifesteal
      TriggerType: OnAttackHit
      LifestealRatio: 0.1        ← 回伤害的10%
      LifestealMaxHPRatio: 0

Skill Config:
  SkillType: None
```

#### 示例 5：范围光环 — 「燃烧光环」

### 3.4 场景设置

1. 确保 Player 物体上有 `PlayerStat` 组件（已有）
2. 给 Player 物体添加 `BlessingManager` 组件
3. 将创建好的 `BlessingDatabase` SO 拖入 `BlessingManager` 的 `Database` 字段
4. 勾选 `Show Debug Gizmos` 可在 Scene 视图中查看范围可视化

### 3.5 购买祝福（程序接口）

在美琴购买界面调用以下代码即可装备祝福：

```csharp
var blessingManager = player.GetComponent<BlessingManager>();
blessingManager.EquipBlessing(blessingData);
```

`EquipBlessing` 会自动：卸下旧祝福 → 装备新祝福 → 应用被动效果 → 设置主动技能 → 存档。

### 3.6 存档说明

- 祝福 ID 保存在 `player.json` 的 `Current_Blessing` 字段中
- 游戏启动时 `BlessingManager.Start()` 自动从存档加载祝福
- 只有购买新祝福才会更改，死亡/切换关卡不影响

## 四、扩展指南

### 策划添加新祝福

在 `BlessingDatabase` SO 的列表中添加条目，填写参数，**无需写任何代码**。

### 程序添加新被动效果

1. 在 `BlessingEnums.cs` 的 `EffectType` 枚举添加值
2. 在 `Effects/` 下新建类，继承 `EffectHandlerBase`，实现 `OnEquip` / `OnUnequip` / `OnTrigger`
3. 在 `EffectHandlerBase.cs` 的 `EffectHandlerFactory._registry` 添加一行注册

### 程序添加新主动技能

1. 在 `BlessingEnums.cs` 的 `SkillType` 枚举添加值
2. 在 `Skills/` 下新建类，继承 `SkillHandlerBase`，实现 `Activate` / `Deactivate`
3. 在 `SkillHandlerBase.cs` 的 `SkillHandlerFactory._registry` 添加一行注册

### 程序添加新 Buff 类型

1. 在 `BuffContainer.cs` 的 `BuffType` 枚举添加值
2. 在 `BuffContainer.ApplyTick` 中添加处理逻辑
3. 在敌人 AI 中通过 `HasBuff(NewType)` 检查来应用行为变化
